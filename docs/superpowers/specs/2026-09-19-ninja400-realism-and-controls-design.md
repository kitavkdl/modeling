# 닌자 400 실물감·조작·진행 개선 설계

날짜: 2026-09-19 · 상태: 승인(대화에서) · 이전 스펙: `2026-09-19-ninja400-assembly-design.md`

## 1. 배경과 목표

사용자 실사용 피드백 다섯 가지를 한 번에 해결한다.

1. 오토바이가 "너무 네모 박스"다 → 실물 윤곽에 가깝게.
2. 키 삽입이 너무 어렵다.
3. 엔진음이 실제와 다르다.
4. 시동 후 키보드로 브레이크·클러치·기어 조작을 하고 싶다.
5. 모든 단계에 건너뛰기가 있어야 한다.
6. 3D라서 보는 각도·위치에 따라 부품이 커서를 따라오지 않는다.

**실제 3D 모델 파일 도입은 시도 후 기각했다.** 무료·재배포 가능 라이선스의 닌자 400 모델은
Sketchfab의 CC-BY 하나뿐이었고, 열어 보니 차체·바퀴·엔진이 한 덩어리로 녹아 붙은 스캔/생성물이라
분해는 물론 통짜 표시에도 부적합했다(사용자 확인 후 기각, 2026-09-19). 그래서 **코드로 생성하는
곡면 형상**으로 실물감을 올린다. 모델 분할 파이프라인(`scripts/split-gltf.mjs`, `/dev/parts` 뷰어)은
제대로 된 모델이 생겼을 때를 위해 남긴다.

## 3. 엔진 형상 프리미티브 추가 (`src/engine/types.ts`, `geometry/`)

기존 `Primitive`에 네 가지를 더한다. 모두 mm 단위, 원점 규칙은 기존과 같이 **밑면(또는 시작점) 기준**이다.

```ts
| { type: 'lathe'; profile: [number, number][]; segments?: number; angle?: number }
  // profile: [반지름, 높이] 점열을 y축 둘레로 회전. 탱크·머플러·헤드라이트 렌즈·림·피스톤.
| { type: 'tube'; path: Vec3[]; radius: number; segments?: number; radial?: number; closed?: boolean }
  // Catmull-Rom 경로를 따라 관을 뽑는다. 프레임 트러스·배기관·핸들바·라디에이터 호스·브레이크 라인.
| { type: 'extrude'; shape: [number, number][]; depth: number; bevel?: number; holes?: [number, number][][] }
  // xy 평면 다각형을 +z로 밀어낸다(중심 기준, z −depth/2..+depth/2). 스프로킷·디스크·브래킷·계기판.
| { type: 'loft'; sections: Vec3[][]; closed?: boolean; smooth?: boolean }
  // 같은 점 수의 단면 폴리라인들을 차례로 이어 면을 만든다(끝 뚜껑 없음). 카울·시트·테일·펜더·탱크 측면.
```

- `geometry/curved.ts`가 각 타입을 `THREE.BufferGeometry`로 만든다(`LatheGeometry`, `TubeGeometry` + `CatmullRomCurve3`,
  `ExtrudeGeometry` + `Shape`, loft는 직접 인덱스 생성 후 `computeVertexNormals`). 결과는 **입력 객체를 키로 WeakMap 캐시**하고,
  단위 변환(×MM)은 생성 시 한 번만 한다.
- `PartGeometry`는 새 타입을 `<mesh geometry={…}>`로 그린다. `simple`(고스트)에서도 같은 지오메트리를 쓴다.
- `validateGeometry`: lathe 프로필 2점 이상·반지름 ≥ 0, tube 경로 2점 이상·반지름 > 0, extrude 3점 이상,
  loft 단면 2개 이상·모든 단면 점 수 동일(≥ 3).
- 드래그 잡기 영역은 이제 프리미티브 크기를 알 수 없으므로 **렌더된 그룹의 `Box3`** 로 잡는다(§5).

## 4. 닌자 400 재모델링 (`src/products/ninja400/geometry.ts`, `parts.ts`)

부품 id·순서·작업대·`requires`·도색 대상은 그대로 두고 **형상과 좌표만** 바꾼다. 기준 치수는 `spec.ts`
(휠베이스 1370, 캐스터 24.7°, 크랭크 [−120,430,0], 실린더 20° 전경 등)를 유지한다.

| 부품군 | 형상 | 요점 |
|---|---|---|
| 메인 프레임·서브프레임 | `tube` 트러스(반지름 14~18) | 스틸 트렐리스: 헤드튜브(짧은 lathe)에서 스윙암 피벗까지 양쪽 대각 튜브, 가로 브릿지. 서브프레임은 시트 레일 2본 + 가로대. |
| 연료탱크 | `loft` 8단면 + 위쪽 `lathe` 캡 | 앞이 높고 넓으며 뒤로 좁아지는 실루엣. 무릎 파임. 도색 대상. |
| 시트(라이더·동승자) | `loft` | 탱크 뒤에서 낮아지며 테일로 이어짐. |
| 앞 카울(어퍼) | `loft` 좌우 대칭 셸 + 헤드라이트 구멍 `extrude` 링 | 닌자 특유의 날카로운 이중 헤드라이트 얼굴. 도색. |
| 사이드 카울(좌·우) | `loft` 셸 | 라디에이터를 감싸 뒤로 좁아지는 판. 도색. |
| 테일 카울 | `loft` | 위로 치켜든 테일, 후미등 자리. 도색. |
| 앞·뒤 펜더 | `loft` 아치 | 타이어 반지름 + 20 여유. 도색. |
| 휠(앞·뒤) | 림 `lathe`(안쪽 파임) + 타이어 `torus`(기존) + 5-스포크 `extrude` × 5 | 스포크는 림 안쪽 면에서 허브까지. |
| 브레이크 디스크·스프로킷 | `extrude`(구멍·이빨 다각형) | 지금의 박스 이빨 대신 실제 톱니 윤곽. |
| 프런트 포크 | 기존 원통 유지 + 상부 `lathe` 캡 | 충분히 실물감 있음. |
| 엔진 | 크랭크케이스 `extrude`(측면 윤곽 + bevel 8), 실린더 블록 냉각핀 `lathe` 6단, 헤드 `extrude`, 캠 커버 `loft`, 클러치·제너레이터 커버 `lathe` | 내부 27부품은 그대로 두되 크랭크축 웹은 `extrude`, 피스톤 `lathe`. |
| 배기 | 헤더·집합부·머플러 한 `tube` 경로 체계 | 헤더 2본이 크랭크케이스 앞을 내려와 우측 아래 집합부로, 머플러는 `lathe`(끝 좁아짐). |
| 라디에이터·팬·호스 | 코어 `roundedBox` + 핀 줄무늬는 재질로, 호스 `tube` | |
| 핸들(클립온)·레버·미러 | 그립 `lathe`, 레버 `tube`, 미러 `loft` + `extrude` 스템 | 레버는 마무리 단계에서 회전(§7). |
| 헤드라이트·테일라이트 | 렌즈 `lathe`(얕은 돔) | 램프 재질 유지. |
| 계기판 | `extrude` 판 + 화면 `roundedBox` | |

작업 방식: 부품군마다 `geometry.ts`에 생성 함수를 두고(`tankGeometry()`, `frameTrellis()`, …), 프로필 점열은
함수 안에 상수로 둔다(치수는 `// TODO: 실물 확인` 유지). 좌표는 브라우저로 보며 조정한다. 검증 테스트는
`validateGeometry` 통과, bbox가 실물 외곽(전장 1990 × 전폭 710 × 전고 1120, ±10%) 안에 있는지, 프레임과
엔진·탱크·시트가 겹치지 않는지(bbox 교차 검사)로 한다.

## 5. 드래그 재설계 (`src/engine/scene/DraggablePart.tsx`, `dragMath.ts`)

문제: 수평 판정면은 카메라 앙각이 낮을수록 시차가 크고, 커서가 지평선 위로 가면 교점이 사라져 부품이 멈춘다.

- **이동 평면**: 잡은 순간의 카메라 시선 방향을 법선으로, 잡은 지점(e.point)을 지나는 평면. 매 이동마다
  커서 광선과 이 평면의 교점 + (잡을 때의 부품 위치 − e.point) 오프셋 = 부품 위치. 부품은 어느 각도에서도
  커서 아래에 정확히 머무르며, 지평선 문제는 없다(평면이 카메라를 향하므로 항상 교차).
- **판정은 화면 공간**: 부품 앵커(부품 원점)와 각 고스트 앵커(장착 위치 + 작업대 오프셋)를 NDC로 투영해
  픽셀 거리로 비교한다. 임계값은 `snapMm`/`paintMm`을 **고스트의 카메라 거리에서 픽셀로 환산**한 값
  (`px = mm × MM × (viewportHeight / (2 × dist × tan(fov/2)))`), 최소 18px·최대 120px로 클램프.
  겹쳐 보이면 장착된다 — 각도와 무관.
- `resolveDragTargets`는 순수 함수로 유지하되 입력이 "부품 화면 좌표, 고스트 화면 좌표 목록, 픽셀 임계값"이
  된다. 기존 mm 기반 테스트는 화면 좌표 버전으로 교체.
- **장착 애니메이션 출발점**(`record.from`)은 이동 평면 위의 실제 부품 위치(작업대 로컬 좌표로 변환)다.
- **잡기 영역**: 렌더된 부품 그룹의 `Box3`(첫 프레임에 계산)를 감싸는 투명 박스. 최소 한 변 `grabMinMm`.
- 들어 올림 연출은 없앤다(카메라 정면 평면에서 잡은 지점이 그대로 움직이므로 필요 없음). `hoverMm`는 제거.

## 6. 건너뛰기와 키 부품 (`store.ts`, `Hud.tsx`, `types.ts`, 닌자 `parts.ts`)

- `PartDef.phaseOnMount?: string` — 이 부품이 완전히 장착되면 스토어가 `phase`를 그 값으로 바꾼다. 되돌리면
  직전 phase로 돌아간다(히스토리에 phase 전이를 함께 기록).
- 닌자 400의 **키**를 마지막 정규 부품으로 옮긴다: `id: 'ignition_key'`, `requires: ['paint']`, 도색 뒤,
  `phaseOnMount: 'keyed'`, 카메라는 계기판 정면 클로즈업(거리 900), `snapMm`는 전역값 사용. 일반 부품과 같은
  고스트·드래그·건너뛰기·되돌리기를 쓴다. `finale/Key.tsx`는 삭제, `Finale`은 `keyed`부터 시작한다.
- **건너뛰기 버튼**: HUD 힌트 옆 버튼 하나. 이름 "건너뛰기".
  - `assembly`/`complete`: `skipCurrent()` = 선택 부품의 남은 인스턴스를 `mountAll`과 같은 순차 장착으로 붙인다
    (`from`은 대기 위치). 기존 "전부 장착" 버튼은 이 버튼으로 대체한다.
  - `keyed`: 시동 버튼을 대신 눌러 `running`으로(`advancePhase`).
  - `running`: 버튼 없음(마지막 단계).
  - 스토어 `canSkip` 셀렉터: `sequencing`이 아니고 선택 부품이 있으면 true.
- 키보드 `Enter` = 건너뛰기, `Ctrl+Z` = 되돌리기(기존).

## 7. 주행 조작 (`src/products/ninja400/finale/`)

`throttleState.ts`를 **`rideState.ts`** 로 확장한다. R3F 밖(오디오)에서도 읽는 가변 싱글턴을 유지한다.

```ts
export const ride = {
  throttle: 0,        // 0~1, 목표(입력)
  rpm: 0,             // 현재 회전수(모델이 갱신)
  gear: 0,            // 0 = N, 1~6
  clutch: 0,          // 0 풀림 ~ 1 잡음
  brake: 0,           // 0~1 앞 브레이크
  stalled: false,
  wheelRpm: 0,        // 뒷바퀴
}
```

- **입력**: `↑` 스로틀(누르는 동안 0.35초에 걸쳐 1까지, 떼면 0.25초에 0으로), `↓` 앞 브레이크(누름/뗌),
  `Shift` 클러치(누름/뗌), `←` 기어 다운, `→` 기어 업. 시프트 패턴은 실제와 같이 1-N-2-3-4-5-6: N에서 `←`는 1단,
  1단에서 `→`는 N, N에서 `→`는 2단. **클러치를 잡고 있을 때만** 기어가 바뀐다(아니면 짧은 "걸림" 효과음과 흔들림).
  마우스 그립 드래그는 `ride.throttle`을 같이 쓴다. 키 처리는 `running`일 때만, 입력 필드 포커스 시 무시.
- **모델**(`rideModel.ts`, 매 프레임 dt):
  - 목표 rpm = 아이들 1300 + 스로틀 × (10000 − 1300). 클러치가 풀리고 기어가 들어가 있으면 부하 계수
    `load = 1 − 0.6 × clutchOpen`으로 상승 시정수를 0.25초 → 0.6초로 늦추고, 하강은 0.5초.
  - 뒷바퀴 rpm = 기어가 들어가고 클러치가 풀린 만큼 `rpm / ratio[gear]` (1차 감속 × 기어비 × 2차 감속,
    닌자 400 값: 1차 3.087, 기어 2.929/1.947/1.545/1.333/1.185/1.095, 2차 3.071)를 클러치 풀림 비율로 섞는다.
    브레이크는 뒷바퀴 rpm을 0.2초 시정수로 0으로 끈다(스탠드 위 시연이므로 차체는 안 움직인다).
  - **시동 꺼짐**: 기어가 들어간 상태에서 클러치 풀림 비율 > 0.7이고 rpm < 1100이 0.4초 지속되면
    `stalled = true`: 엔진음 정지, 진동 정지, 계기판 rpm 0, 힌트 "시동 꺼짐 · 시동 버튼". 시동 버튼(또는
    건너뛰기)이 다시 걸면 복귀. 기어가 들어간 채 시동을 걸면 클러치를 잡아야 걸린다(안 잡으면 힌트만).
- **표시**: HUD 우하단 계기: 기어(N/1~6, 큰 글자), rpm 바(0~12000, 레드존 10500~), 클러치·브레이크 표시등.
  3D: 클러치 레버(왼쪽) 당김 회전 15°, 브레이크 레버(오른쪽) 12°, 브레이크등 재질 밝기 ×3, 뒷바퀴 회전,
  기어 변경 시 시프트 레버 짧은 회전.

## 8. 엔진음 v2 (`audio/engineSound.ts`)

API: `start()`, `stop()`, `setRpm(rpm)`, `setThrottle(t)`, `setLoad(l)`, `blip()`(시프트 순간 짧은 흡기 소리).
점화 스케줄(720° 주기, 0°와 180°)은 유지한다.

신호 경로:

```
점화 임펄스(0.6ms 사각 + 지수 감쇠 8~20ms, rpm↑일수록 짧게)
  → 배기 공명 뱅크: BiquadFilter(bandpass) × 3, 주파수 = 기본 공명 95Hz·190Hz·285Hz × (1 + 0.15×스로틀), Q 6~10
  → 머플러 저역통과 1.2kHz(스로틀 0) ~ 2.6kHz(스로틀 1)
  → 마스터
흡기 노이즈: 화이트 → bandpass 400~900Hz(rpm 비례) → 게인 = 스로틀² × 0.25
기계음: 톱니파 rpm×6/60 Hz(캠 체인·기어 휘슬) → highpass 1.5kHz → 게인 0.02
불규칙: 점화 시각 ±1.5% 지터, 점화 세기 ±10%, 아이들에서 ±4% rpm 흔들림
부하: load↑ → 임펄스 세기 ×(1+0.3 load), 배기 공명 Q ×1.3 (묵직해짐)
컴프레서(기존) → destination
```

`firingTimes`/`rpmFor`는 순수 함수로 유지하고 rpm은 이제 외부(`rideModel`)에서 넣는다. 아이들 1300, 최대 10000.
테스트: 스케줄 함수와 필터 파라미터 계산 함수(`resonanceFor(throttle)`, `pulseFor(rpm, load)`)만 순수 함수로
분리해 검사한다.
